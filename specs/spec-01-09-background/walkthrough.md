### 수동 검증

1. **잠김**: E2E. 화면은 내 해석 쓰기로 안내, API 는 403.
2. **실제 연결**: 두 책, `docs/experiments/04-connections/README.md`. connect.v2 에서 9/9 대조 통과, 판마다 7~19초, 0.03~0.06달러.
3. **독자를 평가하지 않음**: 연결 17개(v1 통과 8, v2 9)를 읽었고 평가 문장은 없었다.
4. **새 판**: 같은 답을 판 2 로 저장 → 새 연결, 판 1 의 연결은 DB 에 남음.
5. **다시 모으기**: API 테스트와 화면 테스트로 확인. 실제 실패 수집으로는 하지 않았다 (구독 사용량).
6. **스크린숏**: `docs/design/screens/background-connected.png`, `background-others.png`.

## 🔍 발견 사항

- **E2E 가 남긴 수집이 작업 프로세스를 기다린다.** 시험용 책 21권의 수집이 대기 중이었다. 그대로 작업 프로세스를 띄우면 가짜 책을 실제로 수집해 구독 사용량을 쓴다. 이번에는 손으로 실패 처리했다. E2E 가 수집을 넣지 않게 하는 방법은 아직 없다.
- **`pnpm build` 를 호스트에서 돌리면 compose 의 개발 서버(web)가 흔들린다.** 빌드 직후 E2E 가 페이지를 열지 못했고, `docker compose restart web` 뒤에는 통과했다. 같은 `.next` 를 함께 쓰기 때문으로 보인다. E2E 를 빌드보다 먼저 돌리면 피할 수 있다.
- **E2E 를 동시에 돌리면 첫 컴파일 때문에 화면 이동이 5초를 넘길 때가 있었다** → 기다림 10초 (`playwright.config.ts`). 그 뒤 연속 통과. 이 기기가 잠들어 네트워크가 끊긴 실행(`ERR_NETWORK_IO_SUSPENDED`)이 한 번 있었다.
- **출처의 종류 분류가 틀린 것이 하나 보였다** (주간경향의 재인용이 "직접 한 말"). 읽기 단계의 판단이라 대조로 확인되지 않는다.
- **브라우저 테스트가 처음 한 번 "모듈을 가져오지 못함"으로 실패했다.** Vite 가 새 의존(`@inkle/contract/background`)을 다시 최적화한 뒤에는 통과했다.
- **스코프 훅의 경고**는 spec.md 의 중괄호 경로를 읽지 못해 생긴 오탐이다 (spec-01-08 과 같음).
