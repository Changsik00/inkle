## 📌 결정 기록

| 이슈 | 선택지 | 결정 | 이유 |
|---|---|---|---|

| 페이지 읽기 | CLI 의 웹 가져오기 / 앱이 직접 가져오기 | 앱이 직접 | 공식 문서 확인 결과 CLI 의 웹 가져오기는 원문이 아니라 처리된 결과를 돌려준다. 문장 대조에 쓸 수 없다 |

| 가져온 본문 보관 | 보관 / 인용만 남김 | 로컬 DB 에 보관 | 다시 대조하고 다시 만들기 위해. 다른 사람에게 열기 전에 다시 정한다 (열린 질문에 추가) |

| 목표 종료일 | 날짜 산정 / 정하지 않음 | 정하지 않음 | 날짜를 정할 근거가 없다. 점검 2 에서 남은 범위를 보고 정한다 |

## 💬 사용자 협의

- **주제**: LLM 을 어떻게 부를 것인가
  - **합의**: 초안은 Claude API 였다. 사용자가 "`ANTHROPIC_API_KEY` 방식은 차후에 하고 CLI 모드에서 Claude Code 를 쓰자"고 제안했고, spec 을 고친 뒤 Plan Accept 를 받았다.
- **주제**: ADR 의 확정 시점
  - **합의**: Plan Accept 는 제안 방향으로 ADR 을 작성해도 좋다는 뜻이다. 각 ADR 은 `proposed` 상태로 올리고 PR 검토에서 확정한다.

### 수동 검증

spec.md 의 검증 시나리오 4개 대비.

1. **`findings.md` 의 입력 9개가 ADR 에서 다뤄졌는가**
   - **Result**: 충족. 9번은 일부만 풀었다.

   | 입력 | 다룬 곳 |
   |---|---|
   | 1. 출처 검증은 필수 단계 | ADR-004 §2 (찾기 → 가져오기 → 읽기 → 대조) |
   | 2. 출처의 종류를 저장 | ADR-004 §3. "요약만 확인"은 화면에 나가지 않는 상태로 바꿈 |
   | 3. 배경과 시선은 책 단위로 재사용 | ADR-002 §1 |
   | 4. 수집은 오래 걸린다 | ADR-001 §2, §3 (작업 프로세스), ADR-004 §7 (시점과 노출) |
   | 5. "얼마나 흔한 읽기인가" | ADR-002 §2 |
   | 6. 오독 지적에 근거의 종류 | ADR-002 §5, ADR-004 §5 |
   | 7. 글쓴이 구분 | ADR-002 §3 |
   | 8. 장르는 책의 속성 | ADR-002 §4 |
   | 9. 한국어 자료의 접근성 | ADR-004 §8 (열지 못하면 쓰지 않음). 일반 독자의 글이 검색에 잘 오르지 않는 문제는 풀지 못했다고 ADR 에 적음 |

2. **`docs/goals.md` 의 원칙 9개와 어긋나는 결정이 없는가**
   - **Result**: 어긋나는 것을 찾지 못했다.

   | 원칙 | 지키는 곳 |
   |---|---|
   | 먼저 쓰고, 그다음 본다 | ADR-001 §4, ADR-004 §7 |
   | 쓰는 것은 한 번이면 된다 | ADR-002: 독자가 글로 쓰는 필수 자료는 내 해석뿐 |
   | 오독은 근거와 함께, 해석에는 우열 없음 | ADR-002 §5, ADR-004 §5. 시선에 점수나 순위 속성이 없다 |
   | 사실과 해석을 구분한다 | ADR-004 §2 (인용 대조), ADR-002 (배경 항목과 시선이 다른 개념) |
   | 실제 사람의 시선이 먼저다 | ADR-002 §2, ADR-004 §6 |
   | AI 는 독자를 평가하지 않는다 | 독자의 성향이나 수준을 담는 자료가 모델에 없다. 문구는 이후 spec 의 지시문에서 지킨다 |
   | 내 글과 AI 글을 섞지 않는다 | ADR-002 §3 |
   | 원본을 보존한다 | ADR-005 |
   | 개인 데이터는 기본 비공개 | ADR-003 |

3. **"내 해석을 저장하기 전에는 다른 시선이 API 에서도 나오지 않는다"를 구조로 설명할 수 있는가**
   - **Result**: 충족. 도메인 모듈에서 막고 (ADR-001 §4), 책 단위 자료를 모임 없이 읽는 HTTP API 를 만들지 않으며, 작업 진행 상황은 상태만 내준다 (ADR-004 §7). 수집 자체는 해석을 쓰는 동안 진행되므로, 통합 시나리오 2 의 "LLM 호출도 일어나지 않는다"는 독자 단위 작업(연결, 비교)에만 해당한다. 시나리오 문구는 고치지 않았다 (아래 발견 사항).

4. **각 ADR 에 채택하지 않은 선택지와 이유가 있는가**
   - **Result**: 충족. ADR-001 4개, 002 3개, 003 3개, 004 5개, 005 3개.

## 🔍 발견 사항

- **통합 시나리오 2 와 ADR-004 §7 이 어긋난다.** 시나리오는 "내 해석 저장 전에는 이를 위한 LLM 호출도 일어나지 않는다"고 적는데, ADR-004 는 책 단위 수집을 모임 시작 때 미리 돌린다. 수집 결과를 내주지 않는다는 점은 같다. 시나리오 문구를 고칠지, 미리 수집을 포기할지는 사용자 결정이 필요하다.
- **구독으로 자기 스크립트를 돌리는 것이 허용되는지 문서가 명시하지 않는다.** 토큰 발급 명령이 "CI 와 스크립트"용이라는 설명과, 구독은 "개인의 통상적인 사용"을 전제로 한다는 설명이 있을 뿐이다. ADR-004 의 부정적 결과에 적었다.
- **ADR-004 의 가정 네 가지는 실제로 돌려 보지 않았다.** 문서 확인까지만 했다. spec-01-03 의 첫 작업으로 넣었다.
- 공식 문서 확인에서 CLI 참조 문서의 일부(`--tools`, `--system-prompt`)와 도구 참조 문서의 웹 가져오기 설명은 페이지가 잘려 요약으로 확인했다. 원문 문장을 직접 보지 못했다.
- 문자열 대조는 인용이 본문에 있다는 것만 보장한다. 인용이 설명을 뒷받침하는지는 보장하지 못한다.
- spec-01-01 의 ship 을 손으로 커밋해 `sdd ship` 의 상태 전환이 돌지 않았다. phase 표의 상태를 직접 `Merged` 로 고쳤다. 이번에는 `sdd ship` 을 쓴다.
