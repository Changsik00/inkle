## 배경 및 문제 정의

### 현재 상황

`docs/goals.md` 와 `backlog/phase-01.md` 에 제품 목표와 흐름(책 등록 → 내 해석 → 배경 → 다른 시선 → 비교 → 토론과 노트)이 정리되어 있다. 코드는 없다. 이 흐름이 실제로 쓸모 있는지는 한 번도 확인하지 않았다.

### 문제점

- 지금의 경쟁 상대는 일반 AI 채팅이다. 그보다 낫지 않으면 만들 이유가 없는데, 현재 계획대로면 spec 6개를 구현한 뒤에야 이를 알 수 있다.
- 아키텍처 결정(spec-01-02)에 필요한 사실을 모른다. 실제 평론과 독자 반응이 검색으로 얼마나 찾아지는지, 출처가 믿을 만한지, 책 본문 없이 오독을 짚을 수 있는지.
- `docs/goals.md` 열린 질문 세 가지(장르, 배경 노출 시점, 오독 판별 가능성)가 답 없이 남아 있다.

### 해결 방안

읽은 책 2권(소설 1, 비문학 1)으로 전체 흐름을 AI 채팅에서 손으로 돌려 보고, 같은 책을 일반 채팅에 물어본 결과와 비교한다. 결과를 기록해 "계속 만든다 / 고쳐서 다시 실험한다 / 멈춘다"를 판단하고, 열린 질문에 답한다.

## 요구사항

1. 흐름의 각 단계를 그대로 붙여 넣어 쓸 수 있는 프롬프트가 있다 (내 해석 질문, 배경, 다른 시선, 비교, 토론, 노트). 소설용과 비문학용 표현 차이를 포함한다.
2. 비교 대상인 일반 채팅용 프롬프트가 있다 ("내 해석 + 다른 해석을 알려줘" 수준의 한 번 질문).
3. 사용자가 책 2권에 대해 두 방식을 모두 수행하고, 책마다 기록을 남긴다. 기록에는 다음이 들어간다.
   - 내 해석 원문과 각 단계의 AI 응답
   - 출처 점검: 제시된 출처를 모두 열어 보고 "내용을 담고 있음 / 담고 있지 않음 / 열리지 않음"으로 분류
   - 실제 시선과 AI 해석의 개수, AI 해석끼리 비슷한지 여부
   - "책과 어긋나는 곳"으로 짚인 항목마다 맞는 지적인지 여부
   - 달라진 생각이 있었는지와 그 내용
   - 일반 채팅과 비교해 나은 점과 못한 점
   - 걸린 시간과 번거로웠던 곳
4. 결과 문서가 phase-01 점검 1 의 판단(계속 / 수정 후 재실험 / 중단)과 그 근거를 담는다. 판단은 사용자가 내린다.
5. 결과 문서가 열린 질문 세 가지에 답하고, 그 답이 `docs/goals.md` 와 `backlog/phase-01.md` 에 반영된다.
6. 결과 문서가 spec-01-02 로 넘길 입력을 정리한다 (웹 검색 필요성, 출처 검증 방식, 시선의 구성, 장르별 차이).

## Out of Scope

- 코드, 스크립트, 자동화 (API 호출 포함)
- 아키텍처 결정과 기술 선택 (spec-01-02)
- 프롬프트 최적화. 판단에 필요한 만큼만 고친다
- 3권 이상의 실험

## 핵심 전략

| 컴포넌트 | 전략 | 이유 |
|:---:|:---|:---|
| **비교 기준** | 같은 책, 같은 내 해석으로 inkle 방식과 일반 채팅을 나란히 수행 | 성공 기준 3(일반 채팅보다 나은가)을 미리 잰다 |
| **배경 노출 시점** | 한 권은 내 해석을 쓴 뒤에 배경을 보고, 다른 한 권은 쓰기 전에 본다 | 열린 질문에 느낌이 아니라 경험으로 답한다 |
| **출처 점검** | 제시된 출처를 전부 직접 연다 | 성공 기준 4 의 달성 가능성과 검증 장치의 필요성을 확인한다 |
| **기록** | 책마다 한 파일, 같은 양식 | 두 권을 비교하고 spec-01-02 의 근거로 쓴다 |
| **판단** | 기준을 실험 전에 적어 둔다 | 결과를 보고 기준을 맞추는 일을 막는다 |

점검 1 판단 기준 (실험 전 고정):

- **계속**: 2권 모두에서 달라진 생각이 1개 이상 있고, 1권 이상에서 일반 채팅보다 낫다고 평가하며, 내용을 담고 있지 않은 출처가 전체의 10% 이하다.
- **중단 검토**: 2권 모두에서 일반 채팅보다 낫지 않다.
- **수정 후 재실험**: 그 사이의 모든 경우. 무엇을 고칠지 결과 문서에 적는다.

## 검증 계획

코드가 없으므로 자동 테스트는 없다.

```bash
ls docs/experiments/01-manual-flow/
# README.md prompts.md record-template.md book-1.md book-2.md findings.md
```

수동 검증 시나리오:
1. `prompts.md` 의 프롬프트를 새 채팅에 그대로 붙여 넣는다 — 기대 결과: 추가 설명 없이 각 단계가 진행된다.
2. `book-1.md`, `book-2.md` 를 양식과 대조한다 — 기대 결과: 빈 항목이 없다.
3. `findings.md` 를 읽는다 — 기대 결과: 점검 1 판단과 근거, 열린 질문 세 가지의 답이 있다.
4. `docs/goals.md` §열린 질문을 본다 — 기대 결과: 답이 나온 질문이 남아 있지 않다.
