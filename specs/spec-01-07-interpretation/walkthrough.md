## 📌 결정 기록

| 이슈 | 선택지 | 결정 | 이유 |
|---|---|---|---|
| 질문 수 | 두세 개 / 넷 | 넷(수동 실험 그대로), 하나 이상 답하면 저장 | 실험에서 넷 모두 답했고 각각 다른 것을 묻는다. Plan Accept 로 확정 |
| 질문 묶음의 판 | 문구만 저장 / 묶음 판(`fiction-v1`)을 함께 저장 | 판을 함께 저장 | 질문을 고쳐도 과거 해석의 뜻이 바뀌지 않게 (ADR-005) |
| 판 번호 | 앱에서 계산 / 한 SQL 문 + 유일 제약 + 다시 시도 | 한 문장 + 유일 제약, 겹치면 최대 5번 다시 시도 | 동시에 저장해도 1~5 가 겹치지 않음을 테스트로 확인 |
| 문(門)의 자리 | 각 API 처리 / 애플리케이션 층 함수 하나 | `requireUnlocked` 하나 | 이후 spec 의 읽기 API 가 모두 같은 판단을 거친다. 다른 사용자의 모임은 잠김 여부도 알리지 않는다 |
| 임시 저장 | useState + effect / useSyncExternalStore | `useSyncExternalStore` 로 localStorage 를 읽음 | effect 안에서 상태를 바꾸면 React lint 가 막는다. 서버 렌더링에서는 임시본 없음으로 그리고 브라우저가 이어받는다 |
| 내 글 잉크 | 화면에서 클래스 덮어쓰기 / 부품의 변형 | `Textarea` 에 `tone="me"` 변형 | `@shadcn/lint` 가 공통 부품의 겉모양 덮어쓰기를 막는다 (DESIGN.md text-me) |
| 방금 저장한 판 | 조회를 다시 받을 때까지 기다림 / 저장 결과를 바로 보여 줌 | 바로 보여 줌, 조회와 비교해 최근 판 | 저장 직후 화면이 다시 쓰기 모드로 깜빡이지 않게 |
| `/sessions/{id}` | 단계를 읽는 페이지 / Next.js redirects | redirects 로 내 해석 주소로 | 지금 단계가 하나뿐. 단계가 늘면 다시 본다 |
| 떠날 때 묻기 | 앱 안 링크 이동까지 막기 / 창 닫기·새로고침만 | 창 닫기·새로고침·주소 이동(beforeunload)만 | Next.js App Router 는 앱 안 이동을 막는 공식 방법이 없다. 앱 안에서 다른 화면으로 가도 임시본은 남는다 |

ADR 로 새로 남길 결정은 없다 (문은 ADR-004 §7 의 구현, 질문 묶음의 판은 ADR-005 의 적용).

### 수동 검증

1. **모임 시작**: E2E 로 확인. 주소 `/sessions/{id}/interpretation`.
2. **임시본**: E2E 에서 새로고침 뒤에도 남음.
3. **떠날 때 묻기**: 브라우저 테스트로 beforeunload 확인. 앱 안 링크 이동은 묻지 않는다 (위 결정).
4. **저장과 잉크**: 스크린숏 `docs/design/screens/interpretation-saved.png` — 내 글이 만년필 파랑, "내가 씀 · 판 1 · 날짜".
5. **고쳐 쓰기**: E2E 에서 판 2. DB 에서 판 1 이 남는 것은 저장소 계약 테스트가 확인.
6. **지난 모임**: 스크린숏 `book-detail-sessions.png`.
7. **빈 저장**: 화면 테스트에서 서버에 보내지 않고 이유를 보여 줌.

## 🔍 발견 사항

- **책을 지울 때 모임이 막는다** (외래 키). 책 지우기 기능은 없지만, 개발 DB 의 시험 자료를 지울 때는 모임을 먼저 지워야 한다.
- **E2E 를 처음 고친 직후 한 번 실패했다가** 이후 세 번 연속 통과했다. 원인은 확인하지 못했다. 다시 나오면 살펴본다.
- **스크린숏을 찍으려고 개발 DB 의 책과 모임을 모두 지웠다** (이 spec 과 spec-01-06 에서). 손으로 등록해 둔 책이 있었다면 함께 지워졌다.
- 기존 E2E 의 "모임 시작은 눌리지 않는다" 확인을 "눌린다"로 바꿨다.
- 읽기 모드에서 "내 해석" 제목과 첫 줄 사이 간격이 넓다. 다음 화면을 만들 때 함께 다듬는다.
