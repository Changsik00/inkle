## 🎯 배경 및 목표

### 현재 상황

책을 읽고 나면 "내가 제대로 읽은 건가, 남들은 어떻게 읽었나"가 궁금하다. 독서 모임에 가면 다양한 의견과 작품 배경을 들을 수 있지만, 시간과 장소의 제약이 크고 모임이 끝나면 대화가 남지 않는다.

기존 독서 앱은 서재 관리와 리뷰 공유에 집중하고 있어 이 문제를 직접 다루지 않는다. 또한 사용자가 없는 초기에는 "다른 독자의 의견"을 보여줄 수 없다.

이 phase 는 다른 사용자 없이도 독서 모임의 핵심 경험을 얻을 수 있도록, LLM 을 모임 상대로 삼는 1인용 제품을 만든다. 아직 저장소에는 확정된 아키텍처와 코드가 없다.

### 목표 (Goal)

만든 사람 본인이 로컬 docker 환경에서 책 한 권에 대해 다음 흐름을 끝까지 수행할 수 있다.

1. 책 선택
2. 내 해석 먼저 쓰기
3. 배경과 작가의 의도 보기 (출처 포함)
4. 다른 시선 보기와 내 해석과의 비교
5. 시선 하나를 골라 토론
6. 달라진 생각을 노트로 정리

### 성공 기준 (Success Criteria) — 정량 우선

1. 실제로 읽은 책 5권에 대해 위 6단계 흐름을 끝까지 수행한다.
2. 그 5권의 배경 정보에 표시된 모든 사실에 출처가 붙어 있고, 직접 확인했을 때 틀린 사실이 0건이다.
3. 5권 중 4권 이상에서 "다른 시선"이 내가 생각하지 못한 관점을 1개 이상 제시했다고 스스로 평가한다.
4. 내 해석을 저장하기 전에는 다른 시선이 화면과 API 어디에서도 노출되지 않는다 (자동 테스트로 검증).
5. `docker compose up` 한 번으로 전체 환경이 뜨고, 재시작 후에도 데이터가 유지된다.

### spec-01-01 — 아키텍처 결정

- **요점**: 구현 전에 정해야 할 구조적 결정을 ADR 로 확정한다 (코드 없음, 문서만).
- **방향성**: 아래 다섯 가지를 각각 선택지와 근거를 비교해 ADR 로 남긴다. 결과에 따라 이후 spec 의 범위와 순서를 재검증한다.
  1. 앱 구조 — 단일 웹 앱인가, 프론트와 백엔드 분리인가. 언어와 프레임워크 포함
  2. 데이터 모델 — "시선"을 AI 와 사람이 쓴 것 모두 담는 하나의 개념으로 둘 것인가
  3. 사용자 식별 — 인증이 없는 지금도 모든 데이터에 사용자 식별자를 둘 것인가
  4. LLM 근거 — 배경 정보의 사실 확인 방식 (웹 검색과 출처 표기)
  5. 원본과 파생물 — 대화·노트를 원본으로 보존하고 이후 위키를 파생물로 만들 수 있는 저장 구조
- **참조**:
  - `docs/goals.md` §원칙, §열린 질문
- **연관 모듈**: `docs/decisions/`

### spec-01-02 — 프로젝트 뼈대와 로컬 환경

- **요점**: 확정된 아키텍처대로 빈 프로젝트, docker 환경, 데이터베이스, 테스트 실행기를 갖춘다.
- **방향성**: `docker compose up` 으로 앱과 DB 가 뜨고, 테스트와 lint 가 한 명령으로 돈다. `sdd config precheck` 에 등록한다. 현재 워킹트리에 남아 있는 미커밋 Next.js 뼈대는 ADR 결과에 따라 살리거나 버린다.
- **참조**:
  - spec-01-01 의 ADR
- **연관 모듈**: 프로젝트 루트, docker 설정

### spec-01-03 — 책 선택

- **요점**: 책을 검색하거나 직접 입력해 등록한다.
- **방향성**: 외부 도서 검색 API 를 쓰되, 키가 없거나 결과가 없을 때를 위해 수동 입력을 항상 제공한다. 서재 관리 기능으로 확장하지 않는다.
- **참조**:
  - `docs/goals.md` §하지 않을 것
- **연관 모듈**: 책 도메인, 외부 API 연동

### spec-01-04 — 내 해석 쓰기

- **요점**: 책에 대한 내 해석을 질문 두세 개에 답하는 형태로 적어 저장한다.
- **방향성**: 저장 전에는 다른 시선을 볼 수 없도록 서버에서 강제한다 (성공 기준 4). 한 책에 대해 다시 읽고 다시 쓸 수 있는 구조로 둔다.
- **참조**:
  - `docs/goals.md` §원칙 "먼저 쓰고, 그다음 본다"
- **연관 모듈**: 읽기 기록 도메인

### spec-01-05 — 배경과 작가의 의도

- **요점**: 작품이 쓰인 시대, 작가의 삶과 의도, 알려진 평가를 출처와 함께 보여준다.
- **방향성**: LLM 의 기억에만 의존하지 않고 웹 검색으로 확인한 내용에 출처를 붙인다. 확인하지 못한 내용은 "확인하지 못함"으로 표시한다. 내 해석을 쓰기 전에도 볼 수 있게 할지는 `docs/goals.md` 열린 질문에서 결정한다.
- **참조**:
  - `docs/goals.md` §원칙 "사실과 해석을 구분한다"
  - spec-01-01 의 LLM 근거 ADR
- **연관 모듈**: LLM 연동, 책 도메인

### spec-01-06 — 다른 시선과 비교

- **요점**: 서로 다른 해석 서너 개를 제시하고 내 해석과 겹치는 곳, 갈리는 곳, 다루지 않은 곳을 보여준다.
- **방향성**: 채점하지 않는다. 각 시선에 AI 가 쓴 것임을 표시한다. LLM 이 책을 잘 모를 때는 그 사실을 드러낸다.
- **참조**:
  - `docs/goals.md` §원칙 "채점하지 않는다", "AI와 사람을 구분한다"
- **연관 모듈**: LLM 연동, 시선 도메인

### spec-01-07 — 토론

- **요점**: 시선 하나를 골라 대화를 이어간다.
- **방향성**: 대화 전체를 원본으로 저장한다 (이후 위키의 재료). 응답은 스트리밍으로 보여준다.
- **참조**:
  - `docs/goals.md` §원칙 "원본을 보존한다"
- **연관 모듈**: LLM 연동, 대화 도메인

### spec-01-08 — 노트로 정리

- **요점**: 토론 뒤 달라진 생각을 한 편의 글로 남긴다.
- **방향성**: LLM 이 내 해석과 토론 내용을 바탕으로 초안을 제안하고, 사용자가 고쳐서 확정한다. 확정된 노트는 사용자의 글이며 원본으로 보존한다.
- **참조**:
  - `docs/goals.md` §핵심 경험 6
- **연관 모듈**: 노트 도메인

## 🧪 통합 테스트 시나리오 (간결)

> 본 phase 의 Done 조건 중 하나. 구현 위치와 실행 명령은 spec-01-02 에서 확정합니다.

### 시나리오 1: 책 한 권의 전체 흐름
- **Given**: 빈 데이터베이스와 실행 중인 로컬 환경 (LLM 과 외부 API 는 테스트용 대역 사용)
- **When**: 책을 등록하고, 내 해석을 저장하고, 배경과 다른 시선을 보고, 시선 하나와 토론한 뒤 노트를 확정한다
- **Then**: 각 단계의 결과가 저장되어 있고, 환경을 재시작한 뒤에도 모두 조회된다
- **연관 SPEC**: spec-01-03 ~ spec-01-08

### 시나리오 2: 먼저 쓰고, 그다음 본다
- **Given**: 책은 등록했지만 내 해석을 저장하지 않은 상태
- **When**: 다른 시선을 화면과 API 로 요청한다
- **Then**: 두 경로 모두 거부되고, 시선 생성을 위한 LLM 호출도 일어나지 않는다
- **연관 SPEC**: spec-01-04, spec-01-06

### 시나리오 3: 출처 없는 사실은 표시하지 않는다
- **Given**: 웹 검색 결과가 비어 있도록 설정한 테스트 대역
- **When**: 배경과 작가의 의도를 요청한다
- **Then**: 사실로 단정한 문장 없이 "확인하지 못함"으로 표시된다
- **연관 SPEC**: spec-01-05
