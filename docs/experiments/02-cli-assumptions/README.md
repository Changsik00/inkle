# 실험 02: ADR-004 의 가정 확인

> spec-01-03, 2026-11-17. ADR-004 "검증이 필요한 가정" 네 가지를 실제로 돌려 본 기록.
> 스크립트: `scripts/spike/cli-check.sh` (가정 1~3), `scripts/spike/fetch-text.mts` (가정 4). 일회성이며 제품 코드가 쓰지 않는다.

## 결과

| 가정 | 결과 | 어디서 돌렸나 |
|---|---|---|
| 1. 컨테이너 안에서 구독 토큰으로 CLI 가 동작한다 | **확인하지 않음.** 사용자 결정으로 토큰을 쓰지 않는다. 대신 이 기기에 로그인된 CLI 로 비대화 실행이 되는 것을 확인했다 | 호스트 |
| 2. 비대화 실행에서 웹 검색 도구만 켜고 쓸 수 있다 | **통과.** `--tools "WebSearch"` 로 검색해 주소 3개를 정해진 형식으로 받았다 | 호스트 |
| 3. `--json-schema` 가 한국어가 섞인 결과에서 형식을 지킨다 | **통과.** 3회 모두 형식에 맞았고, 그대로 옮기라고 한 인용 9개가 모두 원문에 문자열로 들어 있었다 | 호스트 |
| 4. 출처 페이지의 본문을 HTTP 요청으로 글자로 뽑을 수 있다 | **통과.** 9곳 모두 열렸다 | 호스트, 컨테이너 |

가정 1 을 확인하지 않았으므로 ADR-004 가 적어 둔 대안을 적용한다: **작업 프로세스는 컨테이너가 아니라 호스트에서 띄운다.**

컨테이너에서 확인한 것은 CLI 설치와 실행(`claude --version`, 비루트 사용자)까지다.

## 가정 1~3 의 세부

실행: `bash scripts/spike/cli-check.sh` (호스트, Claude Code 2.1.326, 모델 지정 없음). 전체 82초.

| 호출 | 도구 | 결과 | CLI 가 보고한 비용 추정치 |
|---|---|---|---|
| 한 낱말 답하기 | 없음 | 답을 받음 | 0.08 달러 |
| 『노인과 바다』 평론 검색 | 웹 검색만 | 주소 3개, 4턴 | 0.40 달러 |
| 글에서 주장 3개와 인용 뽑기 (1회) | 없음 | 3개, 인용 3/3 일치 | 0.31 달러 |
| 같은 호출 (2회) | 없음 | 3개, 인용 3/3 일치 | 0.03 달러 |
| 같은 호출 (3회) | 없음 | 3개, 인용 3/3 일치 | 0.04 달러 |

- 비용은 CLI 의 `total_cost_usd` 값이다. 구독으로 실행했으므로 실제 청구액이 아니라 API 로 냈다면 들었을 추정치다. 다섯 번 합쳐 약 0.87 달러다.
- 아무 도구 없이 한 낱말만 받는 호출도 0.08 달러로 잡힌다. CLI 가 호출마다 싣는 기본 지시문 때문으로 보인다 (확인하지 않음). 같은 호출의 1회와 2~3회 비용이 크게 다른 이유도 확인하지 않았다.
- 결과에 `is_error`, `num_turns`, `structured_output` 이 들어 있었다. 형식에 맞는 결과는 `structured_output` 에서 읽는다.
- 표준 입력을 주지 않으면 CLI 가 3초를 기다린 뒤 경고를 낸다. 스크립트에 `< /dev/null` 을 넣었다. 작업 프로세스도 같은 처리가 필요하다.
- 검색 결과의 설명에는 "검색 결과 요약에 따르면"이라는 표현이 들어 있다. 요약은 후보를 고르는 데만 쓴다는 ADR-004 §2 의 전제와 맞는다. 받은 주소 3개가 실제로 열리는지는 이 실험에서 확인하지 않았다.

한계: 가정 3 의 시험 글은 세 문장짜리다. 긴 기사 본문에서도 인용을 한 글자도 바꾸지 않고 옮기는지는 spec-01-06 에서 잰다.

## 가정 4 의 세부

실행: `pnpm tsx scripts/spike/fetch-text.mts`. 호스트와 컨테이너에서 같은 결과가 나왔다.

spec-01-01 리허설에서 사람이 열어 확인한 출처 7곳과 영어 2곳을 더했다. "찾은 낱말"은 실험 때 그 글에 있다고 기록한 낱말 두 개가 뽑힌 본문에 있는지다.

| 언어 | 사이트 | 응답 | 전체 글자 수 | 기사 본문 글자 수 | 찾은 낱말 |
|---|---|:---:|---:|---:|:---:|
| 한국어 | newstomato.com | 200 | 3,353 | 2,126 | 2/2 |
| 한국어 | m.seoul.co.kr | 200 | 7,528 | 1,971 | 2/2 |
| 한국어 | weekly.khan.co.kr | 200 | 9,613 | 7,893 | 2/2 |
| 한국어 | peoplepower21.org | 200 | 2,028 | 1,147 | 2/2 |
| 한국어 | v.daum.net | 200 | 4,115 | 3,308 | 2/2 |
| 영어 | nybooks.com | 200 | 16,261 | 11,982 | 2/2 |
| 영어 | www.newstatesman.com | 200 | 4,474 | 736 | 2/2 |
| 영어 | en.wikipedia.org | 200 | 40,952 | 27,567 | 2/2 |
| 영어 | www.nobelprize.org | 200 | 2,617 | 702 | 2/2 |

- "전체"는 페이지에서 스크립트와 스타일을 뺀 모든 글자, "기사 본문"은 `@mozilla/readability` 가 고른 부분이다.
- New Statesman 은 기사 본문이 736자뿐이다. 유료 구독 벽에 가려졌을 수 있다 (확인하지 않음). peoplepower21.org 도 1,147자로 짧다.
- 확인한 것은 낱말 두 개씩이다. 실험 때 본 문장 원문은 공개 저장소에 남기지 않아 문장 단위로 대조하지 못했다.
- 실험에서 접속을 거부했던 사이트(한국경제 생글생글)는 주소를 기록해 두지 않아 다시 시도하지 못했다.

## 이후 spec 에 넘기는 것

- 작업 프로세스는 호스트에서 `claude` 를 실행한다. CLI 는 빈 디렉토리에서 실행하고 표준 입력을 닫는다.
- 문장 대조는 "전체"와 "기사 본문" 가운데 어느 쪽에 할지 spec-01-06 에서 정한다. 기사 본문은 메뉴와 댓글이 빠지는 대신 일부가 잘릴 수 있다.
- 호출마다 `total_cost_usd` 를 기록한다 (ADR-004 §1).
