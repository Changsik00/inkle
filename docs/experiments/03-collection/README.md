## v1 → v2 로 고친 것

**문제**: v1 에서는 시선이 작가 본인 쪽으로 쏠렸다. 『채식주의자』는 16개 중 11개가 작가 인터뷰에서 나왔고 독자 글은 하나였다. 수동 실험(`01-manual-flow/rehearsal.md` 알게 된 것 4, 5)에서 본 "독자 글이 검색에 잘 안 나온다"와 같은 문제다. 또 『노인과 바다』를 직접 다루지 않는 글(글쓰기 일반에 대한 인터뷰 정리)에서도 시선이 만들어졌다.

**고친 것** (`packages/backend/src/application/prompts/find.v2.ts`):
- 종류마다 개수를 정했다. 독자 글 3개 이상, 평론·서평 3개 이상(그중 하나 이상은 흔한 읽기와 다르게 읽거나 비판하는 글), 작가 글 2개 이하, 배경 글 1~2개.
- 한 종류가 모자라면 다른 종류로 채우지 말고 더 찾게 했다.
- 이 책을 직접 다루는 글만 고르게 했다.

**결과**: 독자 시선이 1 → 9 (『노인과 바다』), 1 → 5 (『채식주의자』) 로 늘었다. 브런치, 티스토리, Goodreads, 영어 독자 블로그가 들어왔다. 대신 배경 항목이 18 → 10, 25 → 9 로 줄었다. 작가 인터뷰가 배경(작가의 의도, 삶)을 많이 주던 출처였기 때문이다. 배경을 보여 주는 spec-01-09 에서 부족하면 배경과 시선의 찾기를 나누는 방법을 본다.

## 알게 된 것

1. **인용 대조는 통과하지만 설명이 인용보다 넓을 수 있다.** 설명 문장의 일부가 인용 밖의 문장에서 나온 경우가 있었다 (중앙데일리). 이번에 본 것은 모두 같은 글 안에 있었지만, 코드가 이를 보장하지는 않는다. ADR-004 §Consequences 의 "부정" 그대로다.
2. **작가 본인의 말에도 "얼마나 흔한 읽기인가" 가 붙는다.** 작가 발언에 `rare`, `majority` 가 붙는데 뜻이 없다. 흔함 정도는 다른 사람의 읽기에만 붙이는 편이 맞다. 시선을 보여 주는 spec-01-10 에서 정한다.
3. **열렸는데 항목이 없는 출처가 있다.** 번역 오류를 비판한 코리아타임스 기사(v2, 5128자)와 브런치 독자 글 하나(v1)에서는 항목이 하나도 나오지 않았다. 해석보다 번역이나 줄거리를 다루는 글로 보인다. 출처 하나가 빈다는 것 말고 해는 없다.
4. **403 은 사이트마다 정해져 있다.** 한국경제, CounterPunch 가 막았다. 사용자 에이전트를 바꿔 우회하지 않는다.
5. **CLI 는 격리해야 한다.** 격리하기 전에는 호출마다 기기의 MCP 서버(Serena)가 함께 떠 대시보드 창을 열었다. `--strict-mcp-config --setting-sources ""` 를 넣은 뒤 두 번의 수집(CLI 호출 수십 번) 동안 한 번도 뜨지 않았다.
6. **JSON Schema 의 `$schema` 를 빼야 한다.** zod 4 의 `z.toJSONSchema` 가 붙이는 2020-12 표시를 CLI 가 거부했다.

## 중단된 실행

- 기본 모델로 시작한 첫 『채식주의자』 수집(`908865c8`)은 출처 6개를 읽은 뒤 구독 사용량이 바닥나 멈췄다. 그때까지 인용 44/44, 배경 16/16, 시선 11/11 (작가 본인 5).
- 작업 프로세스를 강제로 멈췄더니 수집과 작업이 "진행 중" 으로 남았다. 손으로 실패 처리했고, 이후 같은 일이 나도 2시간이 지나면 새 수집을 막지 않도록 했다 (`blocksNewCollection`).
