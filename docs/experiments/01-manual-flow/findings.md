# 실험 01 결과

> 2026-11-17. 리허설 1회(`rehearsal.md`)와 책 1권(`book-1.md`)의 결과를 정리한다.
> 계획은 책 2권이었으나 사용자가 1권 뒤 "감을 잡았다"며 마쳤다. 비문학과 순서 B(배경 먼저)는 수행하지 않았다.

## 판단

**점검 1: 계속 만든다** (사용자 결정, 2026-11-17).

실험 전에 고정한 기준으로는 "계속"의 조건이 충족되지 않았다. 측정 자체가 되지 않은 항목이 있기 때문이다. 사용자는 읽는 단계(배경, 다른 시선, 비교)에서 효용을 느꼈다는 판단으로 계속하기로 했다. 측정되지 않은 항목은 앱이 생긴 뒤 점검 2 에서 다시 잰다.

| 기준 | 결과 |
|---|---|
| 2권 모두에서 달라진 생각 1개 이상 | **측정되지 않음.** 1권만 수행했고 "달라진 점"을 쓰지 않았다. 사용자의 말은 "다른 의견은 이해가 된 것 같다"까지다 |
| 1권 이상에서 일반 채팅보다 나음 | **측정되지 않음.** 일반 채팅 비교를 하지 않았다 |
| 내용을 담고 있지 않은 출처 10% 이하 | **충족 (조건부).** 사용자에게 보여준 출처 중 내용이 다른 것은 0건. 단 페이지를 열어 확인한 뒤의 수치이고, 확인 전에는 리허설에서 7개 중 2개가 달랐다 |

## 확인된 것

1. **읽는 단계는 끝까지 간다.** 사용자는 내 해석을 쓴 뒤 배경, 다른 시선, 비교를 모두 받아 봤다.
2. **쓰는 것은 한 번까지다.** 내 해석은 질문 4개에 모두 답했다. 그 뒤의 선택(토론할 시선 고르기)과 글쓰기(토론 답변, 달라진 점, 기록용 질문)는 모두 건너뛰었다. 채팅이 아닌 개발 세션에서 진행한 영향도 있을 수 있다.
3. **검색 요약은 출처가 아니다.** 주소는 실제로 열리지만 요약이 글에 없는 주장을 덧붙인다. 페이지를 열어 문장을 대조하면 걸러진다 (리허설 29% → 확인 뒤 0%).
4. **배경을 내 해석에 연결하는 방식은 작동한다.** 두 번 모두 배경 항목 전부를 해석의 특정 부분에 붙일 수 있었고, 작가의 발언이 독자의 해석과 바로 맞부딪혔다.
5. **실제 시선은 충분히 찾아진다 (유명한 책 기준).** 두 번 모두 5~6개를 찾아 AI 가 만든 해석을 덧붙일 필요가 없었다. 일반 독자의 글은 블로그와 왓챠피디아에서 찾았다.
6. **찾아지는 시선은 다수 의견으로 쏠린다.** 『노인과 바다』는 "정신적 승리", 『채식주의자』는 "가부장제에 대한 저항"이 대부분이었다. 사용자의 "돈을 얻지 못해 아쉽다", "현실은 현실"과 같은 방향의 글은 찾지 못했다.
7. **독자의 해석이 다수 의견과 다른 지점이 드러난다.** 6번의 뒷면이다. "내 생각이 남들과 어디서 다른가"라는 처음의 질문에 답이 된다. 틀렸다는 뜻이 아니라 드문 읽기라는 뜻으로 보여줘야 한다.
8. **오독은 짚을 수 있지만 출처를 붙이기 어렵다.** 4가지를 짚었고 출처로 완전히 뒷받침된 것은 1가지(참치가 아니라 청새치)였다. 나머지는 모델의 기억에 근거했다. 줄거리를 확인하는 검색을 따로 해도 해당 대목이 나오지 않았다.
9. **확인 비용이 크다.** 출처를 여는 데 한 번에 4만~10만 토큰이 들었다. 모임 한 번에 두세 번 필요하다.

## 확인하지 못한 것

- 모임 뒤 생각이 달라지는가
- 일반 AI 채팅보다 나은가
- 비문학에서 흐름이 통하는가
- 배경을 내 해석보다 먼저 보여주면 어떤가
- 덜 알려진 책, 신간에서 자료가 찾아지는가
- 짚은 오독이 실제로 맞는 지적이었는가 (사용자 판정 없음)
- 독립된 환경에서의 결과. 책 1 은 프로젝트 목표를 아는 세션에서 진행했다

## 열린 질문의 답

| 질문 | 답 | 근거 |
|---|---|---|
| 소설과 비문학을 둘 다 다룰 것인가 | **소설 먼저.** 비문학은 앱이 생긴 뒤 써 보면서 조정한다. 구조는 장르를 나중에 추가할 수 있게 둔다 | 사용자 결정. 비문학은 실험하지 못함 |
| 배경을 내 해석을 쓰기 전에도 볼 수 있게 할 것인가 | **쓴 뒤에만** (잠정 유지) | 순서 B 를 실험하지 못함. 쓴 뒤에 보여주는 방식은 작동했고, 내 해석과 연결하려면 해석이 먼저 있어야 함 |
| 책 본문 없이 "책과 어긋나는 곳"을 믿을 만하게 짚을 수 있는가 | **부분적으로.** 출처로 확인된 것과 모델의 기억에 근거한 것을 구분해 표시하고, 기억에 근거한 것은 "확인 필요"로 낮춰 보여준다 | 4건 중 1건만 출처 확보. 사용자의 판정이 없어 정확도는 미확인 |

## 흐름의 변경

사용자 결정 (2026-11-17).

- **모임의 본체는 내 해석 → 배경 → 다른 시선 → 비교다.** 비교까지 보면 모임이 저장된다.
- **토론과 노트는 선택 단계다.** 원할 때만 하고, 구현도 뒤로 미룬다.
- **독자가 반드시 써야 하는 것은 내 해석 한 번이다.** 그 밖의 입력은 고르기만 하면 되도록 만든다.
- **효용은 글이 아니라 한 번의 선택으로 잰다.** 모임 끝에 "새로 알게 된 것이 있었나", "생각이 달라졌나"를 고르게 한다. 노트의 "달라진 점"으로 재던 기준을 대체한다.

## spec-01-02 로 넘길 입력

1. **출처 검증은 필수 단계다.** 검색 → 페이지 가져오기 → 문장 대조의 세 단계가 필요하고, 대조를 통과하지 못한 내용은 보여주지 않는다.
2. **출처의 종류를 저장한다.** 직접 인용 / 기자나 편집자의 정리 / 재인용 / 요약만 확인.
3. **배경과 시선은 책 단위로 저장하고 재사용한다.** 같은 책의 자료는 독자마다 다시 찾지 않는다. 독자별로 만드는 것은 "내 해석과의 연결"과 "비교"뿐이다. 비용과 대기 시간을 줄이고, 이후 커뮤니티 단계의 책별 공유 위키로 이어진다.
4. **자료 수집은 오래 걸린다.** 수십 초에서 분 단위다. 내 해석을 쓰는 동안 미리 시작하거나, 진행 상황을 보여주는 비동기 처리가 필요하다. 미리 시작하더라도 결과는 해석을 저장한 뒤에만 노출한다.
5. **시선에는 "얼마나 흔한 읽기인가"가 붙는다.** 다수 의견과 드문 읽기를 구분해 보여줄 수 있어야 한다.
6. **오독 지적에는 근거의 종류가 붙는다.** 출처 확인 / 모델의 기억.
7. **글쓴이 구분은 유지한다.** 나 / AI / 외부 사람.
8. **장르는 책의 속성으로 두고 질문과 표현을 장르별로 바꿀 수 있게 한다.** 지금은 소설만 채운다.
9. **한국어 자료의 접근성.** 접속을 거부하는 사이트가 있었다 (1건). 일반 독자의 글은 블로그와 리뷰 사이트에 있어 검색 결과에 잘 오르지 않는다.
