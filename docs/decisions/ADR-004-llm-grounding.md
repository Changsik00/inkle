# ADR-004: LLM 은 Claude Code CLI 로 부르고, 출처는 앱이 직접 열어 문장을 대조한다

## 📚 Context

수동 실험에서 확인한 것 (`docs/experiments/01-manual-flow/findings.md`).

- 검색 결과의 요약은 원문에 없는 주장을 덧붙인다. 리허설에서 7개 중 2개가 달랐고, 페이지를 열어 문장을 대조한 뒤에는 0건이었다 (입력 1).
- 출처마다 성격이 다르다. 본인의 말을 그대로 옮긴 것, 기자가 정리한 것, 다른 글을 다시 옮긴 것이 섞여 있다 (입력 2).
- 수집은 수십 초에서 분 단위가 걸린다 (입력 4).
- "책과 어긋나는 곳" 4건 중 출처로 뒷받침된 것은 1건이었고 나머지는 모델의 기억이었다 (입력 6).
- 접속을 거부하는 사이트가 있었고, 일반 독자의 글은 검색에 잘 오르지 않았다 (입력 9).

사용자 결정 (2026-11-17): 지금은 `ANTHROPIC_API_KEY` 를 쓰지 않고 Claude Code CLI 를 구독으로 쓴다.

공식 문서에서 확인한 것 (2026-11-17, code.claude.com 의 headless, cli-reference, authentication, tools-reference, legal-and-compliance).

- `claude -p` 로 비대화 실행을 하고, `--output-format json` 과 `--json-schema` 로 정해진 형식의 결과를 받는다. 결과는 `structured_output` 필드에 들어 있고, 형식에 맞는 결과를 내지 못하면 그 필드가 없다. 결과에는 `total_cost_usd` 가 함께 온다.
- `--tools` 로 쓸 수 있는 도구를 제한한다. `""` 는 모든 도구를 끈다.
- `claude setup-token` 이 1년짜리 토큰을 만들고, `CLAUDE_CODE_OAUTH_TOKEN` 환경 변수로 넘기면 브라우저 로그인 없이 구독으로 동작한다. 문서는 이 용도를 "CI 와 스크립트"라고 적는다. `ANTHROPIC_API_KEY` 가 함께 있으면 키가 우선한다. `--bare` 는 이 토큰을 읽지 않는다.
- 웹 가져오기 도구는 페이지 원문이 아니라 별도 모델이 처리한 결과를 돌려준다. 문서가 "설계상 손실이 있다"고 적는다.
- 구독 로그인은 "개인의 통상적인 사용"을 전제로 한다. 제품이나 서비스를 만드는 개발자는 API 키를 써야 하고, 구독 자격으로 다른 사용자의 요청을 대신 처리할 수 없다.

## 🎯 Decision

### 1. LLM 호출 경계

LLM 을 부르는 코드는 하나의 모듈 뒤에 둔다. 나머지 코드는 "지시문과 결과 형식을 주면 형식에 맞는 결과를 받는다"와 "웹 검색을 허용할지"만 안다.

- **지금**: 작업 프로세스가 Claude Code CLI 를 실행한다. 인증은 `CLAUDE_CODE_OAUTH_TOKEN` 이다. 토큰은 커밋하지 않는 환경 파일에 둔다.
- **바꾸는 조건**: 만든 사람 본인이 아닌 사람이 쓰게 되기 전에 Claude API 로 바꾼다. 구독 한도 때문에 수집이 자주 멈추는 경우에도 바꾼다.
- 결과 형식은 `--json-schema` 로 요구하고, 받은 뒤 코드로 한 번 더 검사한다. 형식에 맞는 결과가 없으면 한 번 다시 시도하고, 그래도 없으면 작업을 실패로 기록한다.
- CLI 는 프로젝트 설정이 없는 빈 디렉토리에서 실행한다. 이 저장소의 지침 파일이나 훅이 섞여 들어가지 않게 하기 위해서다.
- 호출마다 모델 이름, 지시문의 판, `total_cost_usd` 를 기록한다. API 로 바꿀 때 비용을 어림하는 근거가 된다.

### 2. 수집 절차

책 한 권의 배경과 시선을 모으는 절차. 네 단계이고 2번과 4번은 LLM 이 아니라 코드가 한다.

| 단계 | 누가 | 하는 일 | 도구 |
|---|---|---|---|
| 1. 찾기 | LLM | 책에 대한 평론, 작가 인터뷰, 독자 반응을 검색해 후보(주소, 누가 한 말인지, 무슨 내용인지)를 낸다 | 웹 검색만 |
| 2. 가져오기 | 코드 | 후보 주소를 직접 열어 본문 글자를 뽑는다 | 없음 (HTTP 요청) |
| 3. 읽기 | LLM | 본문을 읽고 배경 항목이나 시선을 정리한다. 각 항목에 본문에서 **그대로 옮긴 인용 문장**과 출처의 종류를 붙인다 | 없음 |
| 4. 대조 | 코드 | 인용 문장이 본문에 실제로 들어 있는지 문자열로 확인한다. 공백과 따옴표 모양의 차이만 맞춰 준다 | 없음 |

- **대조를 통과한 인용이 하나도 없는 항목은 저장하되 내주지 않는다.** 화면에 나오는 모든 배경 항목과 외부 사람의 시선은 대조를 통과한 인용을 하나 이상 가진다.
- 1단계 검색 요약의 내용은 후보를 고르는 데만 쓰고, 화면에 나가는 문장의 근거로 쓰지 않는다.
- 3단계의 LLM 에게는 도구를 주지 않는다. 가져온 본문에 지시문처럼 보이는 글이 섞여 있어도 할 수 있는 일이 결과 형식을 채우는 것뿐이다.

### 3. 출처의 종류

대조를 통과한 인용마다 종류를 저장하고 화면에 표시한다.

| 종류 | 뜻 |
|---|---|
| 직접 인용 | 말한 사람의 문장이 그대로 실려 있다 (인터뷰 답변, 본인이 쓴 글) |
| 기자나 편집자의 정리 | 글쓴이가 다른 사람의 말이나 생각을 자기 문장으로 옮겼다 |
| 재인용 | 다른 글에 실린 말을 다시 옮겼다 |

실험 기록의 네 번째 종류였던 "요약만 확인"은 화면에 나가는 종류가 아니다. 페이지를 열지 못했거나 대조에 실패한 후보의 상태로만 남긴다.

### 4. 다른 언어의 출처

인용 문장은 원문 언어 그대로 저장하고 대조한다. 한국어로 옮긴 문장은 따로 저장하고 AI 가 옮긴 것으로 표시한다 (ADR-002 글쓴이 구분). 화면에는 둘을 함께 보여준다.

### 5. 책과 어긋나는 곳

비교에서 사실 수준의 차이를 짚을 때 근거의 종류를 붙인다.

- **출처 확인**: 대조를 통과한 인용이 근거다. 그대로 보여준다.
- **모델의 기억**: 인용이 없다. "확인 필요"로 표시하고, 단정하는 표현을 쓰지 않는다.

책 본문은 다루지 않으므로 (`docs/goals.md` §위치) 모델의 기억에 근거한 지적이 많을 것이다. 정확도는 점검 2 에서 잰다.

### 6. AI 가 만든 해석

대조를 통과한 외부 사람의 시선이 3개 미만일 때만 덧붙이고, AI 가 쓴 것으로 표시한다. 기준 수는 spec-01-10 에서 조정할 수 있다.

### 7. 수집 시점과 노출

- 책 단위 수집(위 절차)은 모임을 시작할 때 작업으로 넣는다. 독자가 내 해석을 쓰는 동안 진행된다. 같은 책에 이미 모은 자료가 있으면 넣지 않는다.
- 독자 단위 작업(연결, 비교)은 내 해석이 저장된 뒤에 넣는다.
- **내 해석이 저장되지 않은 모임에는 배경, 시선, 비교를 내주지 않는다.** 이 규칙은 도메인 모듈에서 강제한다 (ADR-001). 책 단위 자료를 모임을 거치지 않고 읽는 HTTP API 는 만들지 않는다. 작업의 진행 상황은 "모으는 중 / 끝남 / 실패"만 내주고 내용이나 개수는 내주지 않는다.

### 8. 열지 못하는 출처

접속을 거부하거나, 로그인이 필요하거나, 본문이 글자로 뽑히지 않는 페이지는 "열지 못함"으로 기록하고 쓰지 않는다. 접근 제한을 우회하지 않는다.

가져온 본문은 다시 대조하고 다시 만들 수 있도록 로컬 DB 에 보관한다. 화면에는 인용 문장만 나간다. 다른 사람에게 서비스를 열기 전에 본문 보관 여부를 다시 정한다 (`docs/goals.md` §열린 질문의 인용 공개 범위).

## 📊 Consequences

- **긍정**: API 키와 사용량 과금 없이 시작한다.
- **긍정**: "출처가 그 내용을 담고 있다"가 모델의 판단이 아니라 코드의 문자열 확인으로 보장된다. phase-01 성공 기준 4(틀린 출처 0건)의 근거가 된다.
- **긍정**: LLM 호출 경계가 하나라 API 로 옮길 때 고치는 곳이 정해져 있다.
- **부정**: 보여줄 자료가 줄어든다. 본문을 열 수 없는 사이트, 글자로 뽑히지 않는 페이지, LLM 이 인용을 조금이라도 바꿔 적은 경우는 모두 빠진다.
- **부정**: 문자열 대조는 인용이 본문에 있다는 것만 보장한다. 그 인용이 설명 문장을 실제로 뒷받침하는지, 인용이 맥락을 벗어나지 않았는지는 보장하지 못한다. 출처의 종류 분류도 LLM 의 판단이다.
- **부정**: 구독 한도에 걸리면 수집이 멈춘다. 호출마다 CLI 를 새로 띄우므로 API 보다 느리다.
- **부정**: 구독으로 자기 스크립트를 돌리는 것이 "개인의 통상적인 사용"에 드는지 문서가 명시하지 않는다. 토큰 발급 명령이 "CI 와 스크립트"용이라고 적혀 있다는 것이 근거의 전부다. 사용량이 한 사람이 책 몇 권을 다루는 수준이라는 전제에서 채택한다.
- **부정**: 일반 독자의 글이 검색에 잘 오르지 않는 문제는 풀지 못했다. 찾기 단계의 검색어로 보완하되, 부족하면 점검 2 뒤에 따로 다룬다.
- **중립**: 수집한 자료는 모은 시점의 것이다 (ADR-002).

### 가정의 확인 결과

spec-01-03 에서 돌려 봤다 (2026-11-17, `docs/experiments/02-cli-assumptions/README.md`).

| 가정 | 결과 | 조치 |
|---|---|---|
| docker 컨테이너 안에서 `CLAUDE_CODE_OAUTH_TOKEN` 으로 CLI 가 동작한다 | 확인하지 않음. 사용자 결정으로 토큰을 쓰지 않고 이 기기에 로그인된 CLI 를 쓴다 | **작업 프로세스를 호스트에서 띄운다.** 토큰을 넣으면 컨테이너에서도 띄울 수 있게 길은 열어 둔다 (미확인) |
| 비대화 실행에서 웹 검색 도구만 켜고 쓸 수 있다 | 통과 | 없음 |
| `--json-schema` 가 한국어가 섞인 결과에서 형식을 지킨다 | 통과 (짧은 글 3회). 긴 본문은 spec-01-08 에서 잰다 | 없음 |
| 한국어 평론과 독자 글의 본문을 HTTP 요청으로 글자로 뽑을 수 있다 | 통과 (한국어 5곳, 영어 4곳) | 없음 |

이에 따라 §1 의 "지금"은 다음과 같이 읽는다: 작업 프로세스는 호스트에서 실행되고, 이 기기의 CLI 로그인을 그대로 쓴다. `CLAUDE_CODE_OAUTH_TOKEN` 은 비워 둔다.

## 🔀 Alternatives

- **Claude API 를 바로 사용**: 형식 강제와 속도가 낫고 사업화 때 바꿀 필요가 없다 — 비채택 이유: 사용자 결정. 혼자 쓰는 단계에서 키 관리와 과금을 미룬다. 경계를 두어 나중에 바꾼다.
- **CLI 의 웹 가져오기 도구에 페이지 읽기를 맡김**: 앱이 페이지를 가져오고 글자를 뽑는 코드를 쓰지 않아도 된다 — 비채택 이유: 원문이 아니라 처리된 결과를 돌려주므로 문장 대조를 할 수 없다. 실험에서 문제가 된 "요약이 원문과 다름"이 그대로 남는다.
- **대조를 LLM 에게 맡김** ("이 출처가 이 내용을 담고 있는가"를 다시 물음): 바꿔 말한 내용도 확인할 수 있어 자료가 덜 빠진다 — 비채택 이유: 확인하는 쪽도 틀릴 수 있어 0건을 보장하지 못한다. 문자열 대조는 틀리는 방향이 "빠뜨림"뿐이다.
- **모델의 기억만 쓰고 출처를 붙이지 않음**: 빠르고 비용이 없다 — 비채택 이유: 일반 AI 채팅과 다를 것이 없고, 원칙 "사실과 해석을 구분한다"와 어긋난다.
- **독자의 해석을 본 뒤에 그에 맞춰 수집**: 내 해석과 맞닿는 자료를 더 잘 찾는다 — 비채택 이유: 책 단위 재사용이 깨지고, 해석을 저장한 뒤 분 단위로 기다려야 한다. 책 단위로 넓게 모은 뒤 연결을 독자별로 만드는 방식을 먼저 해 본다.
