# ADR-005: 원본은 덧붙이기만 하고, 파생물은 무엇으로 만들었는지 남겨 다시 만들 수 있게 한다

## 📚 Context

- 원칙 "원본을 보존한다": 대화와 노트가 원본이고 위키와 그래프는 파생물이다. 파생물은 언제든 다시 만들 수 있어야 한다 (`docs/goals.md`).
- 2단계의 개인 위키와 취향 분석은 내가 쓴 문장을 근거로 삼는다.
- 지시문(프롬프트)과 모델은 계속 바뀐다. 점검 2 에서 품질이 부족하면 지시문을 고쳐 과거 모임의 결과를 다시 만들어 비교해야 한다.
- ADR-004 에 따라 LLM 이 만든 결과와 코드가 확인한 사실이 함께 저장된다.

## 🎯 Decision

### 1. 세 가지로 나눈다

| 구분 | 무엇 | 규칙 |
|---|---|---|
| **원본** | 내 해석, 토론에서 오간 말(내 말과 AI 의 말 모두), 노트의 "달라진 점", 끝의 한 번 고르기 | 고치거나 지우지 않는다. 고쳐 쓰면 새 판을 덧붙이고 이전 판을 남긴다 |
| **수집한 자료** | 출처, 가져온 본문, 대조를 통과한 인용 | 가져온 시각과 함께 보관한다. 다시 가져오면 새 기록으로 덧붙인다 |
| **파생물** | 배경 항목과 시선의 설명 문장, 한국어로 옮긴 문장, 연결, 비교, AI 가 만든 해석, 모임 기록 정리, (2단계) 위키와 그래프 | 다시 만들 수 있다. 다시 만들면 이전 것을 지우지 않고 새 것을 "지금 쓰는 것"으로 표시한다 |

토론에서 AI 가 한 말은 AI 가 쓴 글이지만 원본이다. 그 대화가 실제로 있었다는 기록이고, 내 다음 말이 그 말에 대한 답이기 때문이다.

### 2. 파생물에 남기는 것

파생물마다 아래를 함께 저장한다.

- 무엇을 입력으로 삼았는지 (어느 내 해석의 어느 판, 어느 출처와 인용)
- 어느 모델로 만들었는지
- 어느 지시문의 몇 번째 판으로 만들었는지
- 만든 시각

지시문은 코드 저장소에 파일로 두고 판 번호를 붙인다. DB 에는 판 번호만 적는다.

### 3. 지우기

원본을 고치거나 지우지 않는다는 규칙의 예외는 **사용자 본인의 삭제 요청**이다. 모임을 지우면 그 모임의 원본과 파생물을 실제로 지운다. 책 단위 자료는 남는다.

## 📊 Consequences

- **긍정**: 지시문이나 모델을 바꾼 뒤 과거 모임의 연결과 비교를 다시 만들어 이전 결과와 나란히 볼 수 있다. 점검 2 에서 "고치니 나아졌는가"를 같은 입력으로 비교할 수 있다.
- **긍정**: 2단계 위키는 원본만 읽어 만들면 된다. 지금 저장하는 것으로 재료가 충분한지는 아래 "2단계 재료 확인"에 적었다.
- **긍정**: 화면에 나온 문장이 틀렸을 때 어느 지시문과 어느 출처에서 나왔는지 거슬러 올라갈 수 있다.
- **부정**: 지우지 않으므로 자료가 계속 늘어난다. 혼자 쓰는 단계에서는 문제가 되지 않는다.
- **부정**: 모든 조회가 "지금 쓰는 것"을 골라야 한다. 조회 코드가 조금 복잡해진다.
- **부정**: 같은 입력으로 다시 만들어도 LLM 의 결과는 매번 조금씩 다르다. "다시 만들 수 있다"는 같은 결과가 나온다는 뜻이 아니라 같은 재료로 만들 수 있다는 뜻이다.
- **중립**: 내 해석을 고쳐 쓰는 화면을 만들지는 spec-01-05 에서 정한다. 만든다면 새 판을 덧붙이는 방식이어야 한다.

### 2단계 재료 확인

2단계가 필요로 하는 것과 지금 저장하는 것.

| 2단계가 하려는 일 | 필요한 재료 | 지금 저장되는가 |
|---|---|:---:|
| 책·작가·주제 페이지 | 책, 작가, 내 해석, 배경 항목 | O |
| 여러 권에 걸친 연결 | 내 해석의 문장, 시선, 비교 항목 | O |
| "내가 좋아하는 것"을 내 글을 근거로 보여주기 | 글쓴이가 "나"인 문장 | O (ADR-002) |
| 생각이 어떻게 달라졌는가 | 노트의 "달라진 점", 끝의 한 번 고르기 | 한 번 고르기는 O. 노트는 선택 단계라 없을 수 있음 |
| 주제(여러 책에 걸친 개념) | 주제라는 개념 | X. 지금은 만들지 않는다. 원본에서 뽑아내는 파생물이므로 2단계에서 추가해도 원본을 고칠 필요가 없다 |

## 🔀 Alternatives

- **고쳐 쓰는 저장** (다시 만들면 덮어씀): 구조와 조회가 단순하다 — 비채택 이유: 지시문을 고친 전후를 비교할 수 없고, 화면에 나갔던 문장이 무엇이었는지 사라진다.
- **모든 변경을 사건으로만 저장하고 현재 상태는 계산** (이벤트 소싱): 이력이 완전하다 — 비채택 이유: 혼자 만드는 단계에 구조가 과하다. 필요한 것은 원본의 판과 파생물의 출처 기록 두 가지뿐이다.
- **파생물을 저장하지 않고 볼 때마다 만듦**: 저장할 것이 줄고 항상 최신 지시문의 결과가 나온다 — 비채택 이유: 볼 때마다 LLM 을 불러 느리고, 같은 모임을 다시 열면 내용이 달라져 기록이 되지 못한다.
